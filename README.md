# ADS.KZ CRM

CRM для рекламного агентства и его клиентов: от получения заявки из Meta Lead Ads до оценки её качества и фиксации продажи. Проект объединяет работу с клиентами, аналитику рекламных форм и отдельные кабинеты бизнесов в одном веб-приложении.

Ссылка ведёт на опубликованное приложение. Для работы нужен логин и пароль: каждый клиент видит свой бизнес, а администратор платформы управляет кабинетами. Демонстрацию внутреннего интерфейса можно запросить у автора проекта.

## Какую задачу решает проект

Количество заявок из рекламы само по себе не показывает, насколько они полезны бизнесу. В CRM можно проследить путь заявки, сохранить контекст общения, отметить подходящего клиента и увидеть, какие обращения закончились продажей. При подключении Meta Conversions API система передаёт обратно сигнал о качественном лиде.

Для агентства предусмотрена работа с несколькими бизнесами: у каждого свои заявки и настройки Meta, при этом адрес приложения общий.

## Возможности приложения

| Возможность | Как это работает |
| --- | --- |
| Работа с заявками | Канбан «Новые» → «В работе» → «Подходят» → «Продажи», смена этапа из карточки, архив закрытых обращений. |
| Карточка клиента | Контакты, компания, город, услуга, бюджет, ответы рекламной формы, заметки и комментарии. |
| Получение лидов | Ручное создание или импорт из Meta Lead Ads с проверкой повторов по ID лида. |
| Поиск | По имени, телефону, компании и городу. |
| WhatsApp | Переход в чат из карточки с учётом нажатий и времени первого перехода. |
| Оценка качества | Отметка качественного лида, выделение заявок ниже минимального бюджета, фиксация продажи. |
| Обратная связь в Meta | Отправка события `QualifiedLead`, отображение результата и повторная отправка при ошибке. |
| Аналитика | Количество заявок, качественных лидов и продаж; диаграммы ответов на вопросы рекламной формы. |
| Управление бизнесами | Создание кабинетов, настройка Meta, смена пароля клиента, отключение и восстановление доступа. |

Время первого перехода в WhatsApp отражает действие в CRM; оно не подтверждает отправку сообщения или ответ клиента.

## Что проект показывает работодателю

Проект позволяет оценить работу с полным циклом веб-приложения: интерфейсом, серверной логикой, хранением данных, внешними API и развёртыванием.

- **Разработка под бизнес-процесс.** Статусы заявок, критерии качества, минимальный бюджет и аналитика связаны с ежедневной работой рекламного агентства.
- **Разделение данных клиентов.** Сервер проверяет принадлежность проектов и заявок организации. Подмена ID бизнеса в запросе не даёт клиенту доступ к чужим данным.
- **Управление доступом.** Роли администратора платформы и владельца бизнеса, авторизация по JWT, отзыв сеансов при сбросе пароля или отключении кабинета.
- **Внешние интеграции.** Загрузка лидов и ответов форм из Meta, обработка ошибок, защита от повторного импорта, обратная передача качества.
- **Работа с данными.** Схема базы, миграции, история смены статусов, журнал действий и мягкое удаление проектов.
- **Проверка важных сценариев.** Автоматические тесты доступа, изоляции бизнесов, отзыва сеансов и одновременных запросов к интеграциям разных клиентов.

## Стек и устройство проекта

В проекте находятся две реализации CRM. Опубликованная версия по ссылке в начале README — **`site/`**. Реализация **`api/` + `web/`** запускается отдельно и использует другой сервер и базу данных.

| Часть | Технологии |
| --- | --- |
| Интерфейс опубликованной версии | React 19, TypeScript, Next.js API через vinext, Vite, CSS |
| Сервер опубликованной версии | TypeScript, Cloudflare Workers |
| Хранение опубликованной версии | Cloudflare D1, схема и SQL-миграции Drizzle |
| Публикация | Sites |
| Отдельная Python-реализация | FastAPI, SQLAlchemy, Alembic, Pydantic |
| Интерфейс Python-реализации | React 19, TypeScript, Vite |
| Хранение Python-реализации | SQLite для локального запуска, PostgreSQL для серверного |
| Проверки | Node.js Test Runner, Miniflare, pytest, Vitest, Testing Library |

В опубликованной версии браузер обращается к API по `/api`. Сервер проверяет сеанс и доступ к выбранному бизнесу, затем работает с D1 и подключениями Meta. Настройки интеграций привязаны к конкретному запросу, чтобы параллельные обращения разных бизнесов не смешивали их токены.

Сохранённые настройки Meta шифруются; API не возвращает токены в интерфейс. При переносе базы необходимо сохранять и серверный ключ шифрования. В `site/` он связан с `JWT_SECRET`, в Python-реализации используется отдельный `INTEGRATION_ENCRYPTION_KEY`.

```text
site/
  app/                Интерфейс CRM и маршруты приложения
  lib/crm.ts          API, авторизация и бизнес-логика
  db/                 Схема и подключение базы
  drizzle/            SQL-миграции
  worker/             Точка входа Cloudflare Worker
  tests/              Проверки API и собранного Worker
api/
  app/                FastAPI, модели, Meta и Telegram
  alembic/            Миграции Python-реализации
  tests/              Серверные тесты
web/src/              React-интерфейс для FastAPI
docs/                 Архитектура и технические инструкции
```

## Сценарий демонстрации

1. Войти в кабинет бизнеса и открыть «Заявки».
2. Создать ручную заявку, указав контакты, услугу и бюджет.
3. Открыть карточку, добавить комментарий и перевести заявку в работу.
4. Отметить клиента как подходящего, затем зафиксировать продажу.
5. Открыть «Аналитику» и посмотреть изменение показателей. Для диаграмм ответов нужны заявки из Meta.
6. Под учётной записью администратора платформы открыть «Бизнесы» и показать управление отдельными кабинетами.

## Локальный запуск Python-реализации

Этот способ запускает `api/` + `web/`. Для знакомства с опубликованной версией используйте ссылку в начале файла.

Потребуются Python 3.13 или 3.14 и Node.js 22.13+.

1. Из корня проекта создайте окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r api\requirements.txt
   .\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```

2. Для новой установки скопируйте `.env.example` в `.env`. Задайте `ADMIN_USERNAME`, собственный `ADMIN_PASSWORD`, случайный `JWT_SECRET` длиной не менее 32 символов и полученный ключ как `INTEGRATION_ENCRYPTION_KEY`. Для локальной базы оставьте `DATABASE_URL` из примера. Если `.env` уже настроен, сохраните существующие значения и ключи.

3. Для новой базы примените миграции, создайте администратора и включите управление бизнесами:

   ```powershell
   Set-Location api
   ..\.venv\Scripts\python.exe -m alembic upgrade head
   ..\.venv\Scripts\python.exe -m app.bootstrap
   ..\.venv\Scripts\python.exe -m app.migrate_businesses
   ..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
   ```

4. Во втором терминале из корня проекта запустите интерфейс:

   ```powershell
   Set-Location web
   npm ci
   npm run dev
   ```

Откройте [локальную CRM](http://127.0.0.1:5173) и войдите с заданными учётными данными. [Документация FastAPI](http://127.0.0.1:8000/docs) доступна при работающем сервере.

При последующих запусках достаточно запустить API и интерфейс. `app.bootstrap` предназначен для первоначального создания администратора. Meta не обязательна для ручной работы с заявками; подключения настраиваются в панели «Бизнесы».

## Автоматические проверки

Для опубликованной реализации, из каталога `site/`:

```powershell
npm ci
npm test
npx tsc --noEmit
node node_modules/vinext/dist/cli.js build
node --test tests/runtime.test.mjs
```

`npm test` проверяет миграцию существующих данных, права доступа, кабинеты, отзыв сеансов и изоляцию настроек Meta при одновременных запросах. Последняя команда проверяет собранный Worker в Miniflare с отдельной тестовой D1.

Для Python API, из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest api/tests
```

Для отдельного React-интерфейса, из `web/`: `npm test` и `npm run build`.

## Границы текущей реализации

- В опубликованном приложении Meta синхронизируется по кнопке и каждую минуту, пока открыт раздел заявок. Постоянный фоновый импорт при закрытом браузере в этой версии не реализован.
- Передача качества требует настроенных Dataset ID и токена Conversions API. Без них отметка сохраняется в CRM в ожидании настройки.
- Счётчик качественных лидов показывает достижение заданного порога; похожая аудитория в Meta автоматически не создаётся.
- Telegram-уведомления с сохраняемой очередью и Meta webhook реализованы в Python API. Они не входят в опубликованную версию `site/`.
