# План реализации ADS.KZ CRM

Каждый этап заканчивается работающим backend, frontend, миграцией и проверкой соответствующего сценария. Текущий документ и [архитектура](architecture.md) выполняют этап 0.

| Этап | Результат | Проверка готовности |
| --- | --- | --- |
| 0. Проектирование | Схема данных, потоки, контракты адаптеров, scoring и бюджетное правило | Все исходные требования имеют место в архитектуре или в дальнейших этапах |
| 1. Основа | Docker Compose, PostgreSQL, миграции, FastAPI, React, учётные записи, организации/проекты, роли, аудит, OpenAPI | Админ создаёт проект и менеджера; менеджер не видит чужие проекты |
| 2. Лиды и рабочий процесс | Ручной ввод, полный лид, поиск/фильтры, канбан, комментарии, задачи, WhatsApp click, история статусов, SLA, scoring, дубли, тестовые лиды | Сценарий NEW → CONTACTED → QUALIFIED → WON проходит через UI и API; бюджет ниже порога остаётся на рассмотрении |
| 3. Meta Lead Ads | Верификация и подпись webhook, привязка страницы/формы, fetch через Graph API, mapping, идемпотентный импорт, лог доставок | Официальный тестовый лид попадает в правильный проект один раз; неверная подпись отвергается |
| 4. Аналитика | Dashboard, воронка, качество по источнику/кампании/объявлению, скорость, менеджеры, бюджеты, города, потери, экспорт | Отчёты сверены с известным набором тестовых лидов; отсутствующий spend не превращается в выдуманный CPL |
| 5. Обратная связь Meta | Настраиваемые conversion events, очередь, retries, журнал, тестовый режим, Qualified и Won | Событие подтверждённого этапа отправлено один раз, временная ошибка повторяется, постоянная видна админу |
| 6. Подготовка к запуску | Безопасность, наблюдаемость, резервные копии, руководство Meta setup, HTTPS и проверка реальной формы | E2E заявка из рекламной формы, ответ менеджера, квалификация, отчёт и подтверждённая доставка обратного события |

## Минимальные проверки по ходу работы

- Вебхук: verification challenge, подпись raw body, неизвестная форма, повторная доставка, ошибка Graph API.
- Нормализация: поля формы, город/регион, бюджетный диапазон, разные услуги, сохранение raw payload.
- CRM: права ролей, проектная изоляция, score, приоритет, минимальный бюджет, автоназначение, статусная история, аудит, задачи и SLA.
- Связь: первое нажатие WhatsApp и повторные нажатия, расчёт времени реакции без ложного утверждения об отправленном сообщении.
- Feedback: создание событий при QUALIFIED/WON, стабильный event ID, повторные попытки и тестовый режим без внешней отправки.
- Отчёты: воронка, rates, когорты, бюджеты, города, response time, нулевые знаменатели и фильтры экспорта.

## Данные, необходимые перед подключением реальной рекламы

1. Доступ к Meta Business, странице и форме лидов ADS.KZ; приложение Meta и его разрешения.
2. Домен и сервер с HTTPS для вебхука, политики конфиденциальности и входа в CRM.
3. Утверждённые тексты рекламы и вопросов формы, включая контактные поля и согласие на обработку данных.
4. Контактные данные менеджеров и решение, кто отвечает за заявки; базовые SLA и график работы.

Эти данные нужны для подключения к живому аккаунту. Этапы 1–2 можно сделать локально с тестовыми лидами до получения доступа Meta.
