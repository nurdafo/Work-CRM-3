# Простой интерфейс ADS.KZ CRM

Решение для текущего сценария: CRM использует один человек и один проект ADS.KZ. В базе сохранена возможность нескольких проектов и сотрудников для дальнейшего развития, но ежедневный экран не показывает эти настройки.

## Основное меню

1. **Заявки** — четыре этапа: новые, в работе, подходят, продажи. Закрытые заявки лежат в отдельном архиве. Поиск работает по имени, телефону, компании и городу.
2. **Аналитика** — круговые диаграммы по фактическим вопросам форм Meta. Если ответов нет, раздел показывает пустое состояние.
3. **Настройки** — минимальный рекламный бюджет, смена пароля, статус подключения Meta. Удаление рабочего пространства спрятано в «Дополнительные действия».

## Обработка заявки

Новая заявка → «В работу» → «Подходит» → «Продажа». На любом активном этапе можно отметить «Не подошёл»; такая заявка переходит в архив. Её можно вернуть в работу. Карточка показывает телефон, услугу, бюджет и заметную пометку. Из неё можно позвонить или открыть WhatsApp. Открытие WhatsApp фиксируется как попытка связи; это не подтверждает отправку сообщения.

Бюджет ниже порога только выделяется. Заявка сохраняется, а решение принимает владелец CRM. Для обращений только по CRM и API рекламный бюджет не используется как основание для отметки о низком бюджете.

Пока Meta не подключена, заявки добавляются вручную. Отчёты по стоимости и эффективности рекламы нельзя показывать без реальных данных о рекламных расходах.
